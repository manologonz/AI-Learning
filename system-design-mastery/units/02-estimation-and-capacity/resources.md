# Further resources: Unit 2

- **"Latency Numbers Every Programmer Should Know"** (reference, Jeff Dean's list, widely mirrored on GitHub gists and colin-scott.github.io/personal_website/research/interactive_latency.html) — the interactive version shows how the numbers changed over the years; internalize the *ratios*.
- **"Numbers Everyone Should Know" (Jeff Dean, Stanford talk, "Building Software Systems at Google and Lessons Learned")** (slides/talk) — the origin of back-of-envelope estimation culture at scale; short and full of applied examples.
- **Designing Data-Intensive Applications, Ch. 1 (Describing Load / Percentiles)** (Kleppmann, book) — teaches how to describe load with the right parameters (fan-out for Twitter timelines is the classic example we used).
- **Amazon Builders' Library: "Using load shedding to avoid overload"** (article, aws.amazon.com/builders-library) — connects capacity headroom to real overload behavior; a preview of Unit 10.
- **A calculator/sandbox:** write the TS helpers from the lecture in a scratch file (or a spreadsheet) and re-run the PicShare exam with different assumptions until the arithmetic is second nature.
